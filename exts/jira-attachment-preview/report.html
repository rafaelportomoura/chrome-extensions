Attachment Preview for Jira renders HTML, Markdown and Excalidraw

Implemented, not yet checked on real Jirav1.2.0 · Manifest V3exts/jira-attachment-preview

A Chrome extension that renders HTML, Markdown and Excalidraw attachments in the Jira Cloud attachment viewer, which shows only source code. Version 1.2.0 adds Excalidraw Previews on a pannable, zoomable Canvas. All 150 unit tests pass; a check on a real Jira Cloud page is still pending.

  • The Preview replaces the Source view; a button toggles between them.
  • HTML runs in an opaque-origin sandbox, without the page or cookies.
  • Markdown has tables, highlighted code, Mermaid and front matter.
  • Excalidraw drawings open on a Canvas that pans and zooms.

Who it is for and what it does

For reviewing attachments without downloading them. It acts on .html, .htm, .md, .markdown, .excalidraw and .excalidraw.json; other files stay as they are.

How the content reaches the Preview

Full message sequence
Editor still holding the previous file
  • After a file switch, Jira may keep the old editor. If the text read is the previous file's, the controller reads again, up to 6 times every 250 ms.
  • If the old text persists, it uses REST.
  • If REST fails and the text was only "unchanged", it uses that text: two attachments can share content.
  • Showing the same file again reuses the editor text.
  • A size more than one unit off the displayed size also goes to REST.

Excalidraw drawings open on a Canvas

Opens zoomed to fit; wheel or drag pans, Ctrl/⌘ + wheel or pinch zooms. It follows Jira's theme and makes no network request.

Canvas rules in detail
  • Opens fitted with a 32 px margin; an empty drawing opens at 100%.
  • Ctrl/⌘ + wheel or pinch zooms around the pointer; primary-button drag pans.
  • Bottom-left control: −, the zoom (click for 100%), + and Fit.
  • Fonts are bundled, so drawing makes no network request.
  • Zoom limits are Excalidraw's: 10% (MIN_ZOOM) to 3000% (MAX_ZOOM).
  • + and − step to the next tenth; one wheel event zooms at most 10%.
  • Line and page wheel deltas are read as pixels (16 px per line).
  • The SVG is resized rather than CSS-scaled, so it stays sharp at any zoom.
  • On resize, a drawing the user has not moved keeps its opening view; Fit restores it.
  • Dark theme uses Excalidraw's dark mode; light uses the file's background, white when none is set.
  • Embedded images are inline in the file and drawn with it.
Invalid files

The content script runs parseScene before framing. Text that is not JSON with "type": "excalidraw" and an elements array keeps the Source view, with "not a valid Excalidraw file" next to the download button. An export failure inside the page shows "Excalidraw: <message>" and logs it.

Four states: loading, Preview, Source, error

On error, Jira's Source view stays and the reason shows by the download button.

Error reasons
  • file larger than 5 MB
  • not a valid Excalidraw file
  • issue not found
  • attachment not found
  • Jira returned <status>
  • could not load the file

Internal messages

EVTjira-attachment-preview:editor-requestThe content script asks the page world for the editor text.

Sent with window.postMessage to the page origin. The page world ignores messages from other windows.

Message body

EVTjira-attachment-preview:editor-responseThe page world returns the editor text, or null.

It waits up to 1500 ms for the editor to appear. The content script gives up after 2500 ms and uses REST.

Message body

EVTjira-attachment-preview:readyA sandbox page tells its parent it can render.

Sent by preview.html or excalidraw.html to window.parent with target "*". Both pages share listenForRender from src/preview-render.ts.

Message body

EVTjira-attachment-preview:renderThe parent sends the content to render to the sandbox page.

The iframe has an opaque origin, so "*" is the only target that reaches it. framePreview builds the iframe on the page previewPage(kind) names and sends the message. The page accepts only its parent's message with valid fields; kind now accepts excalidraw.

Message body

EVTjira-attachment-preview:open-tabThe content script asks the background to open the Preview in a new tab.

chrome.runtime.sendMessage. The background stores the snapshot in chrome.storage.session under a UUID and opens tab.html?id=<uuid>. Only on a quota error does it drop stored snapshots; their tabs then show the expired message. The constant is OPEN_TAB_TYPE.

Message body

Jira REST API

GET/rest/api/3/issue/{key}?fields=attachmentLists the issue's attachments to find the viewer's file.

Runs only in the fallback. Picks the attachment with the same name and a size matching the displayed one; on a tie, the most recent.

Security model

  • Each Preview runs in a sandbox="allow-scripts" iframe, opaque origin.
  • Markdown goes through DOMPurify; renderers and fonts ship in the extension.
  • Only permission: storage; scripts only on *.atlassian.net.
Sandbox CSP caveat

The sandbox CSP allows inline scripts, 'unsafe-eval' and remote https: scripts. It is a documented exception to the repo rule: the scripts are the attachment's, which runs in an opaque origin with no access to Jira or the extension. Prototypes that load CDN libraries work, Mermaid's CSV parser uses new Function, and forms and popups stay blocked.

End-to-end result (v1.0.0)
  • HTML rendered with scripts running and cookies blocked.
  • Preview / Source toggle.
  • New tab opened by the background.
  • Markdown with a table, highlighted code and a Mermaid SVG.
  • onerror attribute removed.

Limitations

  • Jira Cloud only (*.atlassian.net); not Data Center, Server or Confluence.
  • Excalidraw Previews are view only: links do not click, embeds show a placeholder.
  • Not checked with the extension loaded on a real Jira Cloud page.
More limitations
  • Relative URLs inside a file do not resolve; absolute URLs load.
  • Reading the editor depends on a Jira internal (cmView); REST takes over if it breaks.
  • The new-tab Preview is a snapshot; it expires when the browser closes or session storage fills.
  • .excalidraw.md stays a Markdown Preview; .excalidraw.svg and .png are left to Jira.
  • The Excalidraw page bundles about 19 MB (renderer and fonts), loaded only for drawings.

Install and share

Install steps
  1. Run pnpm build (or pnpm --filter jira-attachment-preview build).
  2. At chrome://extensions, use Load unpacked on exts/jira-attachment-preview/dist.
  3. Open a Jira Cloud issue and click a supported attachment.

To share: pnpm zip jira-attachment-preview.

Glossary, code map and backlog

Glossary
Attachment viewer
Jira's full-screen modal that opens when an attachment is clicked.
Preview
The attachment rendered by the extension, as its author meant it to be seen.
Source view
Jira's own view of a text attachment, showing its source code.
Content source
Where the text comes from: the viewer's editor first, Jira's REST API as the fallback.
Canvas
New: the endless plane an Excalidraw Preview is drawn on, panned and zoomed.
Snapshot
A copy of a Preview's content taken when it opens in a new tab.
