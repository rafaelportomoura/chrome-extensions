Attachment Preview for Jira mostra HTML e Markdown renderizados

Implementada, falta validar no Jira realv1.0.0 · Manifest V3exts/jira-attachment-preview

Extensão do Chrome que renderiza anexos HTML e Markdown no visualizador de anexos do Jira Cloud, que mostra só o código. Os 84 testes unitários passam, e o e2e no Chromium do Playwright passou de novo. Falta validar numa página real do Jira Cloud.

  • Preview substitui o Source; um botão alterna.
  • HTML roda em sandbox de origem opaca, sem acesso à página nem aos cookies.
  • Markdown tem tabelas, código colorido e Mermaid, tudo empacotado.
  • Aceita até 5 MB e abre o preview em nova aba.
  • Não verificado com a extensão carregada numa página real do Jira Cloud.

Para quem é e o que faz

Serve a quem revisa protótipos HTML e Markdown anexados a cards, sem baixar. Atua em arquivos .html, .htm, .md e .markdown; outros arquivos ficam como estão.

Como o conteúdo chega ao preview

Sequência completa das mensagens
Editor com o texto do arquivo anterior
  • Após trocar de arquivo, o Jira pode manter o editor antigo. Se o texto lido é o do arquivo anterior, o controlador lê de novo, até 6 vezes a cada 250 ms.
  • Persistindo o texto antigo, usa o REST.
  • Se o REST falha e o texto só estava "sem mudança", usa esse texto: dois anexos podem ter o mesmo conteúdo.
  • Mostrar o mesmo arquivo de novo reaproveita o texto do editor.
  • Tamanho diferente do exibido também envia ao REST.

Quatro estados: carregando, preview, source, erro

No erro, o Source do Jira continua visível e o motivo aparece ao lado do botão de download.

Motivos de erro
  • file larger than 5 MB
  • issue not found
  • attachment not found
  • Jira returned <status>
  • could not load the file

Mensagens internas

EVTjira-attachment-preview:editor-requestContent script pede o texto do editor ao page world.

Enviada com window.postMessage para a origem da página. O page world ignora mensagens de outra janela.

Corpo da mensagem

EVTjira-attachment-preview:editor-responsePage world devolve o texto do editor, ou null.

Espera até 1500 ms o editor aparecer. O content script desiste após 2500 ms e usa o REST.

Corpo da mensagem

EVTjira-attachment-preview:readypreview.html avisa ao pai que pode renderizar.

Enviada ao window.parent com destino "*".

Corpo da mensagem

EVTjira-attachment-preview:renderO pai envia o conteúdo a renderizar para preview.html.

O iframe tem origem opaca: "*" é o único destino que o alcança. framePreview, em src/preview-frame.ts, monta o iframe e envia a mensagem. A página só aceita mensagem do próprio pai e com campos válidos.

Corpo da mensagem

EVTjira-attachment-preview:open-tabContent script pede ao background que abra o preview em nova aba.

chrome.runtime.sendMessage. O background grava o snapshot em chrome.storage.session com um UUID e abre tab.html?id=<uuid>. Só em erro de cota, apaga os snapshots guardados e as abas deles mostram a mensagem de expirado. A constante é OPEN_TAB_TYPE.

Corpo da mensagem

API REST do Jira

GET/rest/api/3/issue/{key}?fields=attachmentLista os anexos do card para achar o arquivo do visualizador.

Só roda no fallback. Escolhe o anexo de mesmo nome e tamanho compatível com o exibido; em empate, o mais recente.

Autenticação

Sessão do usuário no Jira (credentials: include, mesma origem).

Parâmetros

Só roda depois do GET anterior. Recusa anexos acima de 5 MB antes de baixar.

Modelo de segurança

  • O preview roda num iframe sandbox="allow-scripts", de origem opaca.
  • Markdown passa por DOMPurify; só o renderizador executa scripts.
  • Renderizador e Mermaid vão dentro da extensão.
  • Única permissão: storage; scripts só em *.atlassian.net.
Ressalva da CSP do sandbox

A CSP do sandbox permite scripts inline, 'unsafe-eval' e scripts https: remotos. É uma exceção documentada à regra do repositório: os scripts são do anexo, que roda em origem opaca, sem acesso ao Jira nem à extensão. Protótipos com bibliotecas de CDN funcionam, e o leitor de CSV do Mermaid usa new Function. Formulários e popups ficam bloqueados.

Testes: 84 unitários e um e2e passaram

Vitest com jsdom. O e2e usou o Chromium do Playwright e um Jira falso.

editor-source.test.ts

Leitura do editor (cmView e rootView), ponte por postMessage, ignora outras janelas, timeout.

file-type.test.ts

Extensões aceitas, leitura do tamanho exibido, vírgula decimal, limite de 5 MB.

markdown.test.ts

Tabelas e tarefas GFM, destaque de código, bloco desconhecido escapado, Mermaid com tema e com erro, remoção de script, handler e javascript:.

messages.test.ts

Validação da mensagem render e do tipo open-tab, iframe em sandbox, só aceita ready da própria janela.

preview-controller.test.ts

Preview por padrão, alternância, fallback REST (inclui editor com tamanho diferente do exibido), editor com o arquivo anterior (nova leitura, REST, texto sem mudança), mesmo arquivo reaberto, arquivo não suportado, limite de 5 MB, erro, troca de arquivo, fechamento, nova aba, controles removidos pelo Jira, tema.

preview-render.test.ts

HTML como documento inteiro, Markdown com tema, ready e render, mensagem malformada.

rest-source.test.ts

Chave do card, escolha do anexo, download sem redirect da CDN, sem chave, sem anexo, mais de 5 MB, erro HTTP.

snapshot.test.ts

Grava e abre a aba, apaga os snapshots só em erro de cota, id ausente ou desconhecido, aba expirada.

viewer.test.ts

Leitura do arquivo e tamanho, observação de abrir/trocar/fechar, posição dos botões, estado de erro, limpeza que restaura o estilo de posição do visualizador.

Resultado do e2e
  • HTML renderizado com scripts e cookies bloqueados.
  • Alternância Preview / Source.
  • Nova aba aberta pelo background.
  • Markdown com tabela, código colorido e SVG do Mermaid.
  • Atributo onerror removido.

Limitações

  • Só Jira Cloud (*.atlassian.net); não cobre Data Center, Server nem Confluence.
  • URLs relativas dentro do arquivo não resolvem; as absolutas carregam.
  • A leitura do editor depende de um interno do Jira (cmView). Se mudar, ou se o editor continuar com o arquivo anterior, o REST assume.
  • O preview em nova aba é um snapshot e expira ao fechar o navegador ou quando o armazenamento da sessão enche e o erro de cota o apaga.

Instalar e compartilhar

Passos de instalação
  1. Rode pnpm build (ou pnpm --filter jira-attachment-preview build).
  2. Em chrome://extensions, use Load unpacked em exts/jira-attachment-preview/dist.
  3. Abra um card do Jira Cloud e clique num anexo suportado.

Para compartilhar: pnpm zip jira-attachment-preview gera o zip com o INSTALL.md e a mensagem de chat.

Glossário, módulos e backlog

Termo novo: Content source

A origem do texto do anexo: o editor do visualizador primeiro, o REST como fallback.

Onde cada tipo vive
  • Theme: src/messages.ts.
  • framePreview: src/preview-frame.ts.
  • PreviewError e TOO_LARGE_REASON: src/preview-error.ts.
  • VIEWER_SELECTOR: src/selectors.ts, usado pelo content script e pelo page world.
  • Campo do elemento do visualizador: ViewerFile.viewer. O testid do Jira media-viewer-popup continua.
